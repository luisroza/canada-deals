# GreatDeals.ca Product Roadmap

**Status:** DRAFT - proposed sequence, awaiting Product Checkpoint
**Date:** 2026-08-11

## Phase 1 - MVP: prove trustworthy deal discovery

**Goal:** prove that Canadian shoppers click, save, and return for evidence-backed offers.

- Electronics, home, and tools category wedge.
- Initial retailer integrations only after permission and data review.
- Responsive web deal feed, search, filters, product pages, and retailer handoff.
- Current CAD price, source, last-checked time, freshness, and confidence states.
- Safe same-product comparison.
- History where permitted and sufficiently complete.
- Saves and target-price email experiment.
- Stale/mismatch reporting.
- Affiliate disclosure and outbound analytics.

**Checkpoint:** product analytics, trust feedback, stale rate, comparison accuracy, and affiliate/data feasibility review.

## Phase 2 - Product validation: improve repeat value

**Goal:** increase usefulness for planned purchases without broadening the data problem too quickly.

- Better product/variant matching and evidence explanations.
- Add retailers only when quality thresholds pass.
- Brand, retailer, and category alerts.
- Low-noise weekly digest.
- Narrow French-language validation for one category or region.
- Buying guides linked to live, non-thin offers.
- User correction workflow and internal review tooling.

**Gate:** expand only if repeat use and data quality support the next category or retailer.

## Phase 3 - Growth: scale qualified demand

**Goal:** acquire more Canadian shoppers and deepen retention.

- High-quality category, retailer, brand, and product SEO pages.
- Editorial collections and seasonal campaigns.
- Browser-extension research and limited prototype.
- Verified community signals, such as user reports or comments, only with moderation capacity.
- More regional and French coverage.
- Optional merchant sponsorship with strict labels and ranking separation.

## Phase 4 - Platform: expand the system carefully

**Goal:** build defensible data and partner capabilities without sacrificing neutrality.

- More permitted retailer/network feeds and data partnerships.
- Native mobile app and push only if web retention justifies it.
- Community submissions, reputation, and moderation if trust metrics remain strong.
- Premium history/alert tools or cashback only after unit economics and compliance review.
- AI for constrained comparison, deal explanation, and price-history questions; never as a substitute for source evidence.

## Explicit sequencing rules

1. Do not build community before freshness and identity quality are measurable.
2. Do not build native apps before web alert retention is proven.
3. Do not build cashback before affiliate reconciliation and compliance are understood.
4. Do not mass-generate SEO pages before each template has unique, current value.
5. Do not expand retailer count at the expense of product matching accuracy.
