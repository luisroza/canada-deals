# ADR-010: Provider-specific affiliate handoff

**Status:** APPROVED - explicit owner decision, 2026-08-27  
**Checkpoint:** implementation remains inside the approved Human Architecture / Data Integration boundary; merchant, content, price, image, and API rights remain separate gates.

> ADR-011 supersedes only this record's no-resolution rule for owner validation. The application may inspect bounded `amzn.to` redirect headers, but still preserves the exact short link and never downloads or scrapes the Product page.

## Context

GreatDeals.ca originally assumed every Product affiliate link was generated by a provider adapter and opened through `/go/{listingId}`. The owner can also create a valid Amazon.ca Special Link in the approved Associates account and paste that finished link into the owner-only panel. Rewriting that link or hiding it behind an internal redirect creates unnecessary attribution and policy risk. Automatically following an `amzn.to` URL during intake can also create non-user traffic and is not required to publish the exact owner-supplied link.

## Options

1. Route every provider through `/go/{listingId}`.
2. Expose every provider tracking URL directly to the browser.
3. Model both link acquisition and handoff mode, with a narrow direct-link exception for owner-provided Amazon links.

## Decision

Use option 3.

- Provider-generated Impact, CJ, and Rakuten links remain `PROVIDER_GENERATED` plus `INTERNAL_REDIRECT` and open through `/go/{listingId}`.
- An owner-provided Amazon.ca link is stored byte-for-byte as `OWNER_PROVIDED` plus `DIRECT_PROVIDER` and is returned only as the final public `href`.
- `/go/{listingId}` must ignore direct-provider links.
- The panel follows ADR-011's bounded `amzn.to` redirect-header validation to fill URL-contained Product identity. Relationship evidence remains manual, and Product-page content is never downloaded or scraped.
- Direct publication requires an active Amazon relationship record, allowed destination/tracking hosts, explicit owner attestation, an Amazon-specific Merchant Policy, and the applicable disclosure. Link approval does not grant Product content, price, availability, image, history, caching, or API rights.
- The application never manufactures, appends, removes, or rewrites Amazon tracking parameters.

## Reasoning

The split preserves the current audited, fail-closed provider boundary while keeping owner-created Amazon links intact. It prevents accidental provider URL construction and avoids automated short-link navigation. Explicit acquisition and handoff fields make the exceptional behavior testable instead of inferring it from a hostname at render time.

## Tradeoffs

- Direct Amazon clicks do not pass through the existing minimal `/go` click event.
- The administrator must supply more evidence and Product identity for shortened links.
- The public API exposes the exact destination only for validated Amazon direct-provider links.
- Amazon publication remains unavailable until the separate Product data policy permits every displayed field.

## Migration path

Migration `20260827151516_AddOwnerProvidedAffiliateHandoff` adds `AcquisitionMode` and `HandoffMode` with provider-generated/internal defaults for all existing rows and a database constraint limiting direct owner-provided rows to Amazon. A future Creators API adapter may create provider-generated Amazon links, but it must be introduced through a separate rights-validated change and must not reinterpret existing owner-provided rows.
